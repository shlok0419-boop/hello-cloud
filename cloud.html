Cloud Computing

Cloud computing means renting computing resources over the internet, on demand, and paying for what you use. This page covers the essential characteristics, service and deployment models, elasticity, the shared responsibility model, pricing, global infrastructure, and core AWS services.

Characteristics Service models Deployment models Elasticity Shared responsibility Pricing Regions and AZs AWS and Azure S3 storage classes

1. Essential characteristics

The US National Institute of Standards and Technology (NIST) defines five characteristics of cloud computing. A service that lacks them is usually just hosting.

CharacteristicMeaningExample
On-demand self-serviceYou provision resources yourself, without calling the providerLaunching an EC2 instance from the console
Broad network accessAvailable over standard networks and devicesUsing a dashboard from a laptop or phone
Resource poolingThe provider serves many customers from shared hardwareYour VM runs on a physical host shared with others
Rapid elasticityCapacity grows and shrinks quicklyAuto Scaling adds servers during a sale
Measured serviceUsage is metered and billedBilled per hour, or per GB stored

2. Service models: IaaS, PaaS, SaaS

The service model decides how much of the stack you manage. Every layer you hand to the provider reduces your work, and also reduces your control.

LayerOn-premisesIaaSPaaSSaaS
Application and dataYouYouYouProvider
Runtime and middlewareYouYouProviderProvider
Operating systemYouYouProviderProvider
Virtualisation, servers, storage, networkingYouProviderProviderProvider
IaaS

Infrastructure as a Service

Virtual machines, storage, and networks. You install the OS and the software.

Examples: Amazon EC2, Azure Virtual Machines, Google Compute Engine

PaaS

Platform as a Service

A ready-made platform for your code. You deploy the application, not the servers.

Examples: AWS Elastic Beanstalk, Azure App Service, Google App Engine

SaaS

Software as a Service

Complete applications delivered through a browser. You configure and use them.

Examples: Gmail, Google Docs, Microsoft 365, Salesforce

4. Elasticity and scalability

Scalability is the ability to handle more load. Elasticity is doing that automatically, adding and removing capacity as demand changes.

Scale up (vertical)

Make one machine bigger, with more CPU and memory. It's simple, but there is a limit, and it often needs a restart.

Scale out (horizontal)

Add more machines behind a load balancer. It's more complex, but it grows much further, and it survives one machine failing.

5. Shared responsibility model

Security is split between the provider and the customer. The provider secures the cloud itself. You secure what you put in it.

Provider

Security of the cloud

Physical data centres, hardware, power, cooling, the hypervisor, and the global network.

Customer

Security in the cloud

Your data, IAM users and permissions, OS patches on EC2, security group rules, and encryption settings.

Real-world meaning

Many cloud data leaks come from customer configuration, such as a public storage bucket or a leaked access key, rather than from a failure inside the provider's data centre.

6. Pricing basics

Reserved or Savings PlansCommit to 1 or 3 years for a lower rateSteady production workloads
SpotSpare capacity at a large discount, which can be interruptedBatch jobs and fault-tolerant work

Costs come from compute hours, storage, data transfer out of the cloud, and forgotten resources. Set a budget and an alert before you start.

7. Global infrastructure: Regions and Availability Zones

Region

A geographic area with several data centres, for example Mumbai (ap-south-1). Choose the region closest to your users, and consider data-residency rules.

Availability Zone (AZ)

One or more separate data centres inside a region, with independent power and networking. Spreading resources across AZs protects you if one site fails. Example: ap-south-1a.

Edge location

Smaller sites close to users, used by content delivery networks such as CloudFront to cache content.

Azure equivalent

Azure also uses Regions and Availability Zones, and it pairs regions so data can be recovered if one fails.

9. S3 storage classes

S3 stores objects (files) in buckets. Each storage class trades cost against how quickly you can get the data back.

ClassUse it forRetrieval
S3 StandardFrequently accessed data, including websitesImmediate
S3 Intelligent-TieringData with unknown or changing access patternsImmediate. Moves data between tiers automatically.
S3 Standard-IAInfrequently accessed data that is still needed quicklyImmediate, with a retrieval fee
S3 One Zone-IAInfrequent data that can be recreated, stored in one AZImmediate, lower durability
S3 Glacier Instant RetrievalArchives accessed about once a quarterMilliseconds
S3 Glacier Flexible RetrievalArchives you rarely needMinutes to hours
S3 Glacier Deep ArchiveLong-term compliance archivesHours, lowest cost
Static website note

A static website on S3 uses the Standard class. Public access requires turning off Block Public Access and adding a bucket policy.

Practice

  1. Pick an app you use, such as Gmail or Google Maps. Classify it as IaaS, PaaS, or SaaS, and explain why in two sentences.
  2. Explain elasticity to someone who has never used the cloud, using a shop during a festival sale as the example.
  3. For a college results portal, choose a deployment model and justify it, including the data and cost trade-offs.
  4. List what AWS manages and what you manage for an EC2 web server. Write it in your own words.
