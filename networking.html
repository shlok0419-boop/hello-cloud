Networking for Cloud

Every cloud service is reached over a network. This page covers the network models, IP addressing and CIDR, subnets, DNS, routing, ports, and a method for finding out why a connection fails.

1. OSI and TCP/IP models

A network model divides communication into layers, so each layer solves one problem. The OSI model has seven layers and is mainly used for teaching and troubleshooting. The TCP/IP model has four layers and is what the internet actually uses.

2. TCP and UDP

TCP

Reliable and ordered

Opens a connection with a three-way handshake, resends lost packets, and delivers data in order. Used by HTTP, HTTPS, SSH, and email.

UDP

Fast and connectionless

Sends packets with no handshake and no delivery guarantee. Used by DNS queries, video calls, and streaming, where speed matters more than perfect delivery.

3. IPv4 addresses and CIDR

An IPv4 address is 32 bits, written as four decimal numbers called octets. Each octet is 8 bits, so it ranges from 0 to 255. For example, 192.168.0.112 is 11000000.10101000.00000000.01110000 in binary.

The CIDR prefix (the number after the slash) says how many leading bits identify the network. The remaining bits identify hosts inside that network.

CIDRSubnet maskTotal addressesUsable hostsTypical use
/8255.0.0.016,777,21616,777,214Very large private networks
/16255.255.0.065,53665,534A cloud VPC, for example 10.0.0.0/16
/24255.255.255.0256254A home or office subnet
/26255.255.255.1926462A small subnet
/28255.255.255.2401614A few servers
/30255.255.255.25242A point-to-point link
/32255.255.255.25511A single specific address, such as a firewall rule
Formula

Host bits = 32 minus the prefix. Total addresses = 2 to the power of the host bits. Usable hosts = total minus 2, because the first address is the network address and the last is the broadcast address.

Public and private addresses

Private addresses can be reused inside many networks, but they are not routed on the public internet. Your home router translates them to one public address using NAT (Network Address Translation).

4. Worked example: splitting a network

Take the network 192.168.1.0/26.

  1. Host bits: 32 minus 26 = 6. Total addresses: 26 = 64.
  2. Block size: 256 minus the mask's last octet (192) = 64. Each subnet starts at a multiple of 64.
  3. Network address: 192.168.1.0
  4. Usable hosts: 192.168.1.1 to 192.168.1.62, which is 62 hosts.
  5. Broadcast address: 192.168.1.63
  6. Next subnet: 192.168.1.64/26

Check your answer with ipcalc 192.168.1.0/26. Install the tool with sudo apt install ipcalc if needed.

5. DNS: names to addresses

The Domain Name System translates names such as google.com into IP addresses. A lookup moves through several servers: your resolver asks a root server, then the server for the top-level domain (.com), then the authoritative server for the domain, which holds the final answer.

Your machine  ->  Local resolver (127.0.0.53 on Ubuntu)
              ->  Recursive resolver (your router, ISP, or 8.8.8.8)
              ->  Root server  ->  .com server  ->  authoritative server
              <-  answer, cached for the TTL (time to live) in seconds

nslookup google.com          # full answer from your resolver
dig google.com +short        # short list of IP addresses
dig MX gmail.com +short      # mail servers for a domain
dig @8.8.8.8 google.com      # ask Google's public DNS directly

6. Routing and the default gateway

A host sends traffic for its own subnet directly. Traffic for any other network goes to the default gateway, usually your router. The routing table decides which route applies.

$ ip route
default via 192.168.0.1 dev enp0s3 proto dhcp metric 100
192.168.0.0/24 dev enp0s3 proto kernel scope link src 192.168.0.112

Read it this way: traffic for any destination not listed goes to 192.168.0.1 through enp0s3. Traffic for 192.168.0.0/24 stays on the local network.

7. Ports and services

An IP address identifies a machine. A port identifies a service on that machine. Ports range from 0 to 65535. Ports 0 to 1023 are the well-known ports.

Check which ports your VM is listening on with ss -tulpn. You saw port 22 open for SSH.

8. Networking in the cloud

Cloud providers rebuild these ideas in software. In AWS, a VPC (Virtual Private Cloud) is your own private network. Inside it you create subnets, route tables that define where traffic goes, and an internet gateway for internet access.

ControlApplies toBehaviour
Security groupAn instance, such as an EC2 serverStateful. If inbound traffic is allowed, the reply is allowed automatically. You write allow rules only.
Network ACLA whole subnetStateless. Inbound and outbound rules are checked separately, so both directions need a rule.

To serve a website from EC2, the security group needs an inbound rule for port 80 (HTTP) or 443 (HTTPS). SSH needs port 22, ideally limited to your own IP address.

9. Troubleshooting ladder

Test from the inside out. Each step rules out one layer, so you don't have to guess.

  1. Interface: ip addr. Does the interface have an IP address?
  2. Gateway: ip route, then ping -c 4 192.168.0.1. Can you reach your router?
  3. Internet by IP: ping -c 4 8.8.8.8. If this works but names fail, the problem is DNS.
  4. DNS: nslookup google.com or dig google.com +short.
  5. Path: traceroute google.com. Stars (*) mean a router didn't reply. That's common and not always a fault.
  6. Service: ss -tulpn to confirm the port is listening, then curl -I http://localhost for a web server.
Common mistake

A successful ping to a name doesn't prove the server is reachable. Ping the IP first, then the name, so you know which layer is failing.

Practice in your VM

  1. By hand, work out the network address, broadcast address, and usable range for 10.0.0.128/25. Then check with ipcalc 10.0.0.128/25.
  2. Run dig @8.8.8.8 google.com +short and compare the result with dig google.com +short.
  3. Run ping -c 3 8.8.8.8 and ping -c 3 google.com. Explain what each result tells you.
  4. Capture traffic in Wireshark on your Windows machine while you run a ping, and filter with icmp.
