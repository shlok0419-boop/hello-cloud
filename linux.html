Unit 1

Linux Fundamentals

Most cloud servers run Linux. Understanding the file system, permissions, processes, packages, and SSH is the foundation for everything else in this project.

Kernel and distros File system Files and directories Permissions Processes Packages SSH Troubleshooting

1. Kernel and distributions

The kernel is the core of the operating system. It manages the CPU, memory, devices, and running programs. A distribution (distro) packages the kernel with tools, libraries, and a package manager. Ubuntu, Debian, Red Hat, and Amazon Linux are all distributions.

Ubuntu uses apt to install software. Red Hat and Amazon Linux use dnf or yum. Most core commands, such as ls, cd, and grep, are identical across all of them.

2. The file system hierarchy

Linux uses a single tree that starts at / (the root). Disks and devices are attached somewhere inside this tree. Each top-level directory has a standard purpose:

DirectoryPurposeExample
/Root of the whole file systemEverything lives under here
/homePersonal files for each user/home/vboxuser
/rootHome folder of the root (admin) userNot the same as /home
/etcSystem-wide configuration/etc/ssh/sshd_config
/varData that changes while the system runs/var/log for logs
/usrInstalled programs and libraries/usr/bin holds most commands
/tmpTemporary files, often cleared on rebootScratch space
/optOptional third-party softwareVendor applications
/devDevice files that represent hardware/dev/sda is a disk
/procVirtual files showing live kernel and process data/proc/cpuinfo

Absolute and relative paths

An absolute path starts at / and always points to the same place: /home/vboxuser/hello-cloud/index.html. A relative path starts from where you are now, so hello-cloud/index.html works only from /home/vboxuser.

Shortcuts: ~ is your home folder, . is the current folder, and .. is the parent folder.

Tip

Run pwd before rm or mv. Most beginner mistakes come from running a command in the wrong folder.

3. Working with files and directories

pwd                         # where am I?
ls -la                      # list everything, including hidden files
mkdir -p ~/lab/a/b          # create nested folders in one step
touch notes.txt             # create an empty file
cp notes.txt backup.txt     # copy a file
cp -r src/ dest/            # copy a folder and its contents
mv old.txt new.txt          # rename or move
rm notes.txt                # delete a file (no recycle bin)
rm -r lab/                  # delete a folder and its contents
cat file.txt                # print a file
less file.txt               # scroll a file (press q to quit)
head -n 5 file.txt          # first 5 lines
tail -n 5 file.txt          # last 5 lines
tail -f app.log             # follow a log as it grows
wc -l file.txt              # count lines
Careful

rm deletes permanently. There is no undo. Check the path with ls first, and never run rm -rf / or rm -rf ~.

Searching

grep "error" app.log            # lines containing "error"
grep -ri "todo" .               # search folders recursively, ignore case
find . -name "*.html"           # find files by name
find /var/log -size +10M        # find files larger than 10 MB
which python3                   # where a command lives

Redirection and pipes

echo "hello" > file.txt        # write, overwriting the file
echo "more" >> file.txt         # append to the file
ls -l | grep "\.html"           # pipe one command's output into another
ps aux | grep "[s]sh"           # brackets stop grep from matching itself

4. Permissions and ownership

Every file has three permission sets: one for the owner, one for the group, and one for others. Each set can include read (r), write (w), and execute (x).

$ ls -l index.html
-rw-r--r-- 1 vboxuser vboxuser 512 Nov 22 08:00 index.html

 -    rw-     r--     r--
 |     |       |       |
 |   owner   group   others
 |
 file type (- = file, d = directory)
NumberSymbolMeaning
7rwxRead, write, and execute
6rw-Read and write
5r-xRead and execute
4r--Read only
0---No access

Each permission has a number: read is 4, write is 2, and execute is 1. Add them within each set. For example, 644 means the owner can read and write (6), and the group and others can read (4 each).

chmod 644 index.html            # owner rw, everyone else r
chmod 600 secret.txt            # owner only
chmod u+x deploy.sh             # add execute for the owner
chmod g-w notes.txt             # remove write for the group
sudo chown vboxuser:vboxuser index.html   # change owner and group
SSH rule

SSH refuses private keys that others can read. Keep ~/.ssh at 700 and private keys at 600.

5. Processes

A process is a running program. Each one has a PID (process ID). systemd is process 1 and starts the other services when the system boots.

ps aux                      # every process with CPU and memory use
ps aux | grep "[s]sh"       # find SSH processes
top                         # live view, press q to quit
sleep 300 &                # run in the background
jobs                        # list background jobs
fg                          # bring the last job to the foreground
kill 1234                   # ask process 1234 to stop (SIGTERM)
kill -9 1234                # force it to stop (SIGKILL)
sudo systemctl status ssh   # check a service
SignalNumberEffect
SIGINT2Ctrl+C from the keyboard
SIGKILL9Stops the process immediately. It can't be caught or ignored.
SIGTERM15Polite stop request. This is the default for kill.

Use kill first. Use kill -9 only if the process ignores it, because the program gets no chance to save its data.

6. Package management

A package manager installs software, resolves dependencies (other packages a program needs), and keeps track of versions. Ubuntu's apt downloads packages from online repositories.

sudo apt update              # refresh the list of available packages
sudo apt upgrade -y          # install updates for installed packages
sudo apt install -y tree     # install a package
apt show tree                # show details about a package
sudo apt remove tree         # remove the program, keep its config
sudo apt purge tree          # remove the program and its config
sudo apt autoremove          # remove unused dependencies
Order matters

Run sudo apt update before install or upgrade. Update refreshes the list. Upgrade installs the newer versions.

7. SSH: secure remote access

SSH (Secure Shell) gives you an encrypted terminal on another machine. It uses a key pair. The private key stays on your computer. The public key is placed on the server, in ~/.ssh/authorized_keys. The server checks that you hold the private key without the private key ever leaving your machine.

FileWherePurpose
id_ed25519Your computer, ~/.ssh/Private key. Never share it. Permissions 600.
id_ed25519.pubYour computer, ~/.ssh/Public key. Safe to copy to servers.
authorized_keysServer, ~/.ssh/Public keys allowed to log in as this user
known_hostsYour computer, ~/.ssh/Fingerprints of servers you have already connected to
ssh-keygen -t ed25519 -C "you@example.com"   # create a key pair
ssh-copy-id vboxuser@192.168.0.112           # install the public key on a server
ssh vboxuser@192.168.0.112                   # log in
ssh -v vboxuser@192.168.0.112                # verbose output for debugging

Common SSH errors

MessageLikely causeFix
Permission denied (publickey)Your public key isn't in the server's authorized_keys, or file permissions are wrongCheck the file, then run chmod 700 ~/.ssh and chmod 600 ~/.ssh/authorized_keys
Connection timed outWrong IP address or a network problemRun hostname -I on the server and check both machines are on the same network
Connection refusedThe SSH server isn't runningsudo systemctl status ssh
REMOTE HOST IDENTIFICATION HAS CHANGEDThe server's key changed, or the connection is being interceptedIf you rebuilt the server, run ssh-keygen -R host. Otherwise investigate before connecting.
Security

Your private key is the key to the server. Never paste it into a chat, screenshot, or Git repository.

8. Troubleshooting checklist

  1. Read the full error. The most useful part is usually the last line.
  2. Check where you are. Run pwd, whoami, and hostname -I.
  3. Check permissions. Run ls -l on the file or folder involved.
  4. Check the service. Run sudo systemctl status ssh.
  5. Read the logs. Run journalctl -u ssh -n 30 --no-pager.
  6. Search the exact error text, or ask an AI tool with the command, the error, and what you already tried.

Practice in your VM

  1. Create ~/lab/a/b with one command, then delete ~/lab.
  2. Create a file, set it to 600, and explain what ls -l shows.
  3. Start sleep 600 &, find its PID with ps aux | grep "[s]leep", and stop it with kill.
  4. Run journalctl -u ssh -n 20 and write down what the first line means.
